# Local setup notes: macOS + Docker smoke test workflow

Hi everyone,

I’m new to Kaggle competitions, so I’m sharing a small local setup note in case it helps other beginners.

This is a tooling/setup note, not a strategy post. I’m not including deck choices, card evaluations, parameters, or match results.

## Background

This is a simulation competition, so the submission is not a CSV file. The submitted package needs to contain an agent that can return:

- the initial deck list on the first call
- selected option indices during the game

For local development, I wanted a quick way to check that my agent package can start a match and return actions in the expected format before thinking about decision quality.

## macOS note

On my macOS environment, the provided simulator library is a Linux binary, so I could not load it directly from a macOS Python process.

The workaround I used is to run quick local checks inside Docker with a Linux Python image.

For Apple Silicon, using a Linux amd64 container was important.

## What I check before submitting

For early development, I found it useful to separate packaging/runtime checks from agent-strength evaluation.

The basic checks I run are:

- the submission package contains `main.py`
- the submission package contains `deck.csv`
- `deck.csv` has exactly 60 integer rows
- the simulator support files are included
- local files such as `.venv`, logs, replays, downloaded data, and credentials are not included
- the agent initial call returns a valid 60-card deck
- a short local match can start and the basic runtime path works

## Why I use short smoke tests first

The purpose of the first local test is not to measure strength.

It is just to catch basic problems such as:

- invalid deck output
- invalid action format
- rejected option indices
- missing files
- import/runtime errors

After those are stable, it becomes easier to look at actual decision quality.

## Notes

This workflow has helped me separate two kinds of problems:

1. packaging/runtime problems
2. agent decision-quality problems

If anyone has a simpler local setup pattern, I’d be interested to compare notes.
