Live score is noisy, so I started using public replays more like a debugging dataset.

The workflow is simple:

1. Let a submission collect enough games.
2. Review losses before changing rules.
3. Put each loss into a small bucket.
4. Reproduce the repeated bucket locally with fixed seeds.
5. Change one thing at a time.

The review row I use is roughly:

| field | example |
| --- | --- |
| episode_id | replay id |
| visible_archetype | broad visible-card bucket |
| seat | first / second |
| first_real_attacker_turn | first meaningful attack turn |
| final_board | active + bench count |
| loss_shape | setup miss / tempo loss / no backup attacker |
| likely_actionable | yes / no / unclear |

The labels I currently use are:

- setup miss
- tempo loss
- no backup attacker
- bench-snipe collapse
- wrong target priority
- resource exhaustion
- deck-out / low-deck risk
- probably variance

This is mostly useful because it stops rule changes based on one bad replay. If the same loss shape shows up several times, I test a narrow change locally.

I also made a small starter notebook that reads public episode JSON files and exports:

- episode summary
- broad visible archetype summary
- visible attack usage summary
- manual loss-label template

It uses the public daily episode dataset as a capped sample, and also handles the index-only dataset case by showing a short note instead of failing silently.

The notebook is intentionally light. Exact deck choices and rule weights can stay in a private review sheet.
