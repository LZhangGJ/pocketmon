Hi, I would like to clarify the allowed use of LLM-based coding assistants during development for this competition.

The rules seem to allow external tools and LLMs as long as they are reasonably accessible to all participants and have minimal/reasonable cost. The rules also mention that a small subscription fee for additional elements of a large language model, such as Gemini Advanced, may be acceptable if it satisfies the Reasonableness Standard.

Given that, are tools such as Codex, Claude Code, Cursor, Gemini Advanced, or similar LLM-based coding assistants allowed for development work, including preprocessing and feature engineering?

To be clear, I am not asking about calling an external API during evaluation. I understand that the submitted agent must not use ingress/egress during evaluation.

My question is about development only:

* Can we use Codex / Claude Code / similar tools to write preprocessing scripts for the competition data?
* Can these tools inspect schema information, column names, dtypes, missing-value summaries, and file paths?
* Can these tools inspect sample rows, card names, card text, IDs, or other competition data during development, if the data is used only for this competition?
* Can we use these tools to generate derived features, tags, embeddings, or other preprocessing outputs, as long as those outputs are used only for this competition and are not published or reused elsewhere?
* Is there any difference between using a cloud-based LLM coding assistant and a local LLM with no external network transmission?

In short, where is the boundary for using LLM coding assistants with competition data during development?

I want to comply with the no-ingress/no-egress rule during evaluation and avoid any reuse or redistribution of Pokémon-related data outside the competition, but I would like to understand what is allowed during normal AI-assisted development.
