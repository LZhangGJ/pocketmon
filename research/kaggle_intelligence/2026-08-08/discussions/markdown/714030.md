#### Message 3481681 — unknown

Thank you for reporting this and for sharing the log.

We reviewed the log and confirmed that this match ended in a draw at 3,000 steps.

The issue was that the simulator had a step limit set to 3,000. This was not the intended behavior for this type of situation. The intended behavior is that, even if an agent enters an infinite loop, the agent should eventually run out of its allotted time, and the player whose agent entered the loop should lose by timeout.

We have already made a fix on the simulator side, and the updated simulator is expected to be released soon.

Thank you again for helping us identify this issue.

#### Message 3484230 — unknown

Posted: 2026-06-30T06:25:47.340Z

Thank you for the follow-up.

As introduced in this topic, we have updated the simulator:
https://www.kaggle.com/competitions/pokemon-tcg-ai-battle/discussion/716045

With this update, even if an agent enters an infinite loop or repeatedly performs rapid non-progressing actions, the match should no longer end in a draw due to the previous step limit. Instead, the step limit has been increased so that the agent is expected to eventually run out of its allotted time, and the player whose agent caused the loop will lose by timeout.

In a real Pokémon TCG match, this type of situation would likely fall within the scope of judge rulings. However, in this competition, there is no human judge during automated simulations. Therefore, we have handled this by increasing the step limit and allowing the match to be resolved by the time limit.

Please note that this update does not retroactively change matches that have already been played. However, for matches played after the simulator update, the behavior should follow the above logic.
