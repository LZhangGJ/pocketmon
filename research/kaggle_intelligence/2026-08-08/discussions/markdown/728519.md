Five submissions a day makes every crashed agent expensive, and most of my early crashes came from three things that are not spelled out anywhere obvious.

The option type is an int, not an enum member. `op.type` comes back as a raw integer, so `op.type.name` raises and any code that assumes an enum dies on the first turn. Compare against integers instead. The values I have confirmed by walking real games:

| option | value |
|---|---|
| PLAY | 7 |
| ATTACH | 8 |
| EVOLVE | 9 |
| ABILITY | 10 |
| DISCARD | 11 |
| RETREAT | 12 |
| ATTACK | 13 |
| END | 14 |

The first call is not a move. On the very first call the observation has no selection, and the agent is expected to return its 60 card deck rather than an index. Returning a move there fails before the game starts.

An illegal index is fatal, not ignored. If you return an index outside the offered options the engine raises and the game does not finish. So the first thing to check on any new agent is not its win rate, it is whether it ever throws.

The fix for all three is the same, which is to run full games locally before spending a submission. The engine ships inside the sample submission folder and runs on CPU, so `battle_start`, `battle_select` and `battle_finish` are enough to play a complete game in a loop. Two details matter when you do this. Alternate which agent moves first, since seating is worth real win rate, and call `battle_finish` before starting the next game because the engine holds one battle at a time.

For a sanity check on my own setup, a simple rule based agent that just orders the option types and takes any lethal attack beats the random sample agent 0.917 over 60 games with seats alternated, and lands on exactly 0.500 against a mirror of itself over 30 games with zero errors. The mirror result is the useful one, since a harness that does not return 0.5 for an agent playing itself has a bug in it.

I packaged the loop, including that baseline as something to measure against, here: https://www.kaggle.com/code/busyaprime/test-your-agent-a-local-matchup-harness
