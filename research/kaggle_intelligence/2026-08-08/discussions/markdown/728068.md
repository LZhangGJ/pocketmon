While testing I found a reproducible segfault (SIGSEGV) in the official game engine (sample_submission/cg, the current 2026-07-17 build). A specific legal 60-card deck crashes the simulator during normal play. Reporting it here so it can be fixed, since we all rely on this engine for evaluation.
Public reproduction notebook:
https://www.kaggle.com/code/shlomoron/ptcg-engine-crash-repro-nb
The notebook uses only the official public API (cg.game.battle_start / battle_select / battle_finish) and the sample agent's own random move selection — nothing custom. It plays self-play games and reports the engine subprocess dying with signal 11.
What it shows (3 decks):
Crashing deck (contains Ninetales #660 + Amarys #1207): engine SIGSEGVs on the first game.
Control A — same deck, Amarys → Basic {R} Energy: 200 games clean.
Control B — same deck, Ninetales → Basic {R} Energy: 200 games clean.
Removing either card stops the crash, which isolates it to the Ninetales × Amarys interaction.
Likely cause (from the public card text + released source, FYI):
Ninetales's attack "Supernatural Shapeshifter" discards the top card of the deck and, if it's a Supporter, uses that Supporter's effect. Amarys is a Supporter with a delayed end-of-turn effect (DelayEffect). When the attack borrows Amarys's effect, the delayed-effect path appears to look up the delay skill on the attacker (Ninetales, which has no delay skill) instead of on the Supporter → null pointer → dereference → crash. (The release build seems to have the relevant assert compiled out.)
